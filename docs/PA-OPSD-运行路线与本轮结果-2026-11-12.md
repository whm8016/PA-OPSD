# PA-OPSD 运行路线与本轮结果

日期：2026-11-12。依据：根目录《开题报告_OPSD自进化_v2.docx》与本地实际脚本。

## 整体思路

把系统想成“资深教师示范，年轻教师练习，再把有效教法总结成教材”。先完成教师数据和单模型基线，再做 OPSD，最后接技能循环。每一步分别验收，不能把 API 数据生成、普通 SFT 和完整自进化当成同一件事。

1. 数据边界：学生只看合法输入 x（历史、当前题、记忆问题）；教师另外看 z（答案、解析等）。564 条严格弱种子划分为 507 条训练、57 条工程验证。它们不是 Gold，也不是全部已经通过教师审核。
2. 教师示范：Diagnoser 找历史依据，Pedagogue 写教学回复，Verifier 独立检查。通过者导出为训练候选，失败者保留在日志分母里。
3. SFT 基线：先让一个模型学会原生 JSON 格式和基本教学表达；只在 assistant token 上计算训练损失。验收单步更新、短训、保存和重载。
4. OPSD：学生在 x 下自己续写，同源教师在 x+z 下对同一段续写给分布监督。API 教师输出文本不能冒充同词表 logits。
5. 技能回流：从训练轨迹提炼成功/失败经验，经隔离数据验证后才激活，再作为教师特权回流 OPSD。候选模型通过新鲜确认集才继承。
6. 冻结评测：比较无技能、技能检索、技能 SFT、技能 OPSD；关闭检索后仍有收益，才能讨论权重内化。Gold 不用于调提示或技能准入。

## 本轮查明的长度问题

用户给出的命令属于教师生成，而非训练。旧日志只保存外部异常类型，无法单凭 BadRequestError 断定原始错误一定来自长度。已有 teacher_real_01.jsonl 两条记录分别为教学审核拒收和接受，未记录长度错误。

确认存在一个可修复的请求膨胀问题：Diagnoser 同时收到完整 student_messages 历史和 history_records，历史重复发送。现在诊断请求只在 history_records 中保留一份完整历史，student_messages 保留系统说明、当前题和记忆问题；其他角色及最终训练消息仍完整保持官方输入。证据序号和原文还原逻辑不变。

这相当于去掉材料里的重复附件，不是删学生历史，也不是更换成短历史任务。旧运行的首条诊断请求为 53,475 输入 tokens，本轮相同样本首次诊断为 33,442 输入 tokens；计数来自对应 API 的 usage。

另一个独立问题在训练默认值：Qwen tokenizer 测得现有合格样本总长 24,825 tokens，默认 max-length=4096 会拒绝。完整 564 条种子的学生提示长度为 22,888～29,386 tokens，中位数 25,308；在额外预留 1,000 输出 tokens 的审计口径下，全部可放入 32,768。此结论只适用于学生提示；OPSD 还需逐条核对教师特权提示和生成预算。API tokenizer 与 Qwen tokenizer 的计数不能混用。

禁止用关闭长度校验或静默截断绕过这两个问题。

本轮用户指定的真实 10 条生成全部完成：9 条通过自动裁判，1 条拒收；共 38 次 API 调用，累计 1,288,440 输入 tokens、8,183 输出 tokens。无 API 长度/网络错误；其中一次回复不是有效 JSON，按既有有界重试处理。全量 55 项测试通过且无跳过，lint 通过。

抽查自动接受记录发现质量疑点：q1095 把历史正确结果升级成“已掌握”并声称学生采用过某计算步骤；q653 把未观测到的方法说成学生实际做法；q4647 采用错误历史作类比来源。它们需复核，不能把自动接受 9 条称为 9 条 Gold 或直接用于正式训练。疑点与样本 ID 保存在 manual_review_smoke10_20261112.json；本轮未降低裁判标准，也未把拒收记录强行改为接受。

本轮真实 10 条生成结果以 outputs/pa_opsd/run_summary_smoke10_20261112.json 为准；原始日志 teacher_smoke10_dedup_20261112.jsonl 保留所有接受、拒绝与重试，accepted_smoke10_dedup_20261112.jsonl 只导出自动通过记录。此前另有 4 条 all.jsonl 探查运行，2 接受、2 拒绝，与本轮有重复，禁止直接拼接成更多独立样本；其调用不计入上述 38 次。

## 重跑与排查

在 D:\OPSD 下运行。若当前 PowerShell 未设置密钥，使用已安装的 python-dotenv 从本地 .env 注入环境，避免手动打印密钥：

```powershell
python -m dotenv run -- python scripts/generate_pa_opsd_teacher.py `
  --input data/pa_opsd/smoke_100_strict/train.jsonl `
  --output outputs/pa_opsd/teacher_smoke10_dedup_20261112.jsonl `
  --accepted-output outputs/pa_opsd/accepted_smoke10_dedup_20261112.jsonl `
  --limit 10 --attempts 2 `
  --teacher-model deepseek-chat --verifier-model qwen-plus
```

只有输入、脚本、模型、地址、重试和输出预算等运行指纹一致才能接着原日志跑。修改这些内容后换新输出文件；原文件不要清空。重跑会跳过已有记录，包括已拒收记录，不会自动重试它们。

- verifier_rejected：教师回复未通过裁判；查看 errors.verifier_issues。裁判也可能误判，必须人工抽检，不能直接把拒收理解成长度错误。
- target_must_have_exactly_five_native_fields：模型输出多/少字段，属于格式错误。
- BadRequestError：供应商拒绝请求；需要原始错误或安全的状态/错误码进一步区分长度、参数或模型支持情况。
- APITimeoutError：接口超时，不能当成坏数据。
- resume_config_mismatch_use_new_output：新旧配置不同，按上面规则换新日志。
- tokens exceed max_length：训练上下文预算不足；先 audit，禁止默默删历史。

## AutoDL 接续点

本机有 8GB 显卡，但当前 PyTorch 为 CPU 版，未安装 peft/trl，也只有 Qwen tokenizer 缓存而无模型权重。本轮不在本机启动完整训练。

同日后续已连接用户新租的 RTX 4090D 24GB 实例，完成 Qwen2.5-7B 的单步与 3 步工程短训、保存和新进程重载。输入为 1 条 24,814 tokens 的完整历史样本；采用 NF4、BF16 冻结 embedding/head、checkpointing、受监督位置 logits 和 CPU 中间数据暂存，3 步训练约 51 秒，PyTorch 分配显存峰值约 18.15 GiB。此前两次 OOM 均保留日志。重载能生成回复，但 JSON 非法转义检查失败，并出现当前题方程；不能视为合格导师或教学效果提升。操作与排查详见 autodl/README_pa_opsd_sft_smoke.md。

AutoDL 首先核对 CUDA、依赖版本、模型路径和 32768 长度审计，再做 SFT 单步/短训、保存和重载，记录显存峰值后扩容训练。现有 environment.yml 固定 Python 3.10、torch 2.8.0、transformers 4.57.1、trl 0.26.0、peft 0.17.1；安装前检查 CUDA 与包版本兼容。

当前 OPSD 入口已有 token 级基础链路，但报告里的显式 action loss、更细动作本体、技能准入、确认集继承和三轮闭环尚未完成。它们是后续实现与实验目标。旧 autodl/README_longtutor_b1.md 的 B1 指未训练模型评测，名称与本报告 B1 单教师 SFT 不同；不能直接套用为本轮训练步骤。

## 调研依据

查询于 2026-11-12，star 为当时页面展示的约数，不作为方法有效性的证据。

- [Self-Distilled Reasoner，arXiv:2601.18734](https://arxiv.org/abs/2601.18734)：同模型用不同上下文，在学生自身轨迹上接受特权分布监督，支撑 OPSD 与普通教师文本 SFT 的区分。
- [OPSD 官方项目，717 stars](https://github.com/siyan-zhao/OPSD)：继续复用现有训练主干与师生对齐逻辑。
- [TRL，19.7k stars](https://github.com/huggingface/trl) 与[官方长度/显存说明](https://huggingface.co/docs/trl/en/reducing_memory_usage)：长度预算、packing 与显存优化是不同工具；不能把 packing 当作完整长样本自动变短。
- [Unsloth，79.4k stars](https://github.com/unslothai/unsloth)：有显存优化训练实现，可在 AutoDL 环境确认后评估集成，不能据此保证任意 GPU 能训练当前长样本。
- [Axolotl，12.7k stars](https://github.com/axolotl-ai-cloud/axolotl)：提供配置化微调框架，但替换训练框架不会消除输入本身的长度。

工程选择：本轮使用现有串联角色和追加日志，先去掉重复数据并保留严格验证。长上下文模型与显存优化可以组合；短历史检索/压缩会改变输入任务，需要单独作为实验条件，不能悄悄替代官方长历史基线。
